## Recommendation

Retain **RAW LCA**, with the actual RAW programme paths and a new equal-cap LCA extension. Recommend the open RAW-derived **DK / ÖB** pair and horizontal **GWP** lettering; information-to-object constructors; element-to-measurement decomposition; a C-stage terminal/four-factor branch; and a distinct D-stage transfer beyond a boundary. Keep the five accepted fabrication mechanisms and use refined curves, filled operating heads and clear negative spaces.

This supersedes the previous Measured Tectonics / Section Gate recommendation. Neither was approved. The prior BR18 / ÖKO study remains a credible alternative, not a statement of user approval. There is no new conceptual product name.

## Original RAW identity: evidence and extension

The actual [RAW programme](https://www.rawproject.eu/) supplies the [white SVG](https://www.rawproject.eu/wp-content/uploads/2024/10/RAW_logo-white.svg). The [EIC project page](https://eic.ec.europa.eu/raw_en) corroborates the programme identity. The current [Tanya explorer](https://tanyatsui.github.io/raw_impact_explorer/) shows RAW PROJECT text; it was not the source of this SVG. The programme mark has three filled paths: geometric R/A and a flowing, asymmetric W. The SVG cap height is 120.52 units and R stem is 21.15 (17.55%). No font name, individual designer, full alphabet or extension policy was found.

Proposal A preserves RAW and adds LCA at the same cap height and stem relationship. The new L/C are original paths; the A deliberately derives from the programme A. B subordinates LCA to RAW; C redraws the L elbow and C terminals with a contemporary curved treatment while preserving RAW. A is the recommended public horizontal wordmark because the tool identity remains explicit. B is suitable only where programme endorsement should dominate. C is more flowing, but its rounded L is less closely related to the source R/A geometry than A. The extra stacked lockup is a placement derivative, not one of the three distinct wordmark refinements. Do not squeeze a full wordmark into a 24px component icon. The original RAW parts are attributed source artwork, not claimed as wholly original design. Brand-custodian review remains outstanding.

## Individual recommendations and competing alternatives

### RAW Material Selector Danish

**A: RAW-derived DK — recommended. Two open custom letters use strong stems, rounded D counter and decisive K junction. Country cue identifies the Danish selector; no border.

Influence: Official RAW R/A bowls and stem ratio; LB Import EPW abbreviation.

Trade-off: DK is readable at 24 px and follows the requested identity. It does not name BR18/Table 7; the component label and tooltip must do that.

**B: DK on an open datum — alternate. Smaller DK sits above a single drafting datum, referencing a catalogue/table baseline without enclosing the letters.

Influence: Previous S2 baseline explored separately from its BR18 text.

Trade-off: More architectural notation, but reduced letter size and a nonessential line weaken recognition at 16 px. No enclosing three-line register.

Raster observation: 24: D counter/K junction clear. 18: both readable. 16: DK remains the strongest selector reading; optional datum adds no useful meaning.

The preserved BR18 / ÖKO baseline option names the source more precisely. It loses here on reading size and relationship to the requested RAW lettering. DK / ÖB needs the full source name in the component label and tooltip. ÖB is not official source branding. The baseline and facade/register studies are retained in the earlier review rather than declared rejected wholesale.

### RAW Construct Element

**A: Inputs become one element — recommended. Three distinct input tokens converge toward a single volumetric analytical object: material, geometry and dimensional information. Tokens are schema cues, not a claim that every mode has three mandatory inputs.

Influence: HB Room construction vs deconstruction; actual RAW constructor contract.

Trade-off: Direction is readable, but tiny connectors become secondary at 16 px. Prism is an analytical element symbol, not a restriction to solid geometry.

**B: Parts lock into one element — alternate. Separated geometric fragments align into one potential element. Gaps express construction before closure.

Influence: User assembly brief; HB aggregate/object distinction.

Trade-off: Strong silhouette, but looks like assembly of physical pieces and can be confused with Wall Assembly. Less faithful to information inputs.

Raster observation: 24: three input tokens and prism distinguish construction. 18: connectors soften. 16: object + incoming cluster survives; exact token semantics do not.

### RAW Physical Properties

**A: Element → measurements — recommended. One intact block branches into a dimension, a plane and a mass-like filled mark. These represent available geometry/quantity/mass outputs, not actual pieces of the material.

Influence: HB Geometry Properties measurement; HB Deconstruct Object direction; current outputs.

Trade-off: Read-only extraction is clear at 24 px; at 16 px it is a block with outgoing measures, not a readable list of all eight outputs.

**B: Whole opens into attributes — alternate. A whole square specimen fans out into a dimension bracket, area tile and round mass marker. The branching operation dominates the source shape.

Influence: User decomposition direction; actual outputs, no edit pencil.

Trade-off: Fewer source details improve 16 px. It could describe any attribute inspector; the volumetric source in A distinguishes element properties from material metadata.

Raster observation: 24: block and measures separate. 18: dimension ticks soften. 16: outward-measurement silhouette survives; outputs require labels.

### RAW Element GWP

**A: RAW-derived GWP — recommended. One continuous horizontal abbreviation, custom open G and P counters with a simplified flowing W. GWP stays fixed across module scopes.

Influence: RAW asymmetric W and geometric R; LB EPW/Area Normalize lettering.

Trade-off: At 24 px all three glyphs survive. At 16 px W detail softens; this is acceptable only with palette labels/tooltips, not as a lone tiny brand mark.

**B: Two-level GWP — alternate. GW above a centred P creates a taller typographic emblem and larger individual glyphs.

Influence: RAW-derived glyphs; abbreviation reading order is the functional constraint.

Trade-off: More legible glyphs at 16 px, but breaks the familiar GWP reading order and resembles initials rather than the indicator. Rejected despite size advantage.

Raster observation: 24: GWP reads horizontally, W has deliberate curve. 18: W curve becomes less expressive. 16: recognisable abbreviation but W is fragile; user readability check needed.

### RAW Construct Machine Process

**A: Inputs become a process record — recommended. Different input tokens converge into a rounded process-event record with an energy trace. It constructs evaluated energy/process data, not a CNC tool or robot. Direction matches Construct Element; the record and energy stroke distinguish the output.

Influence: Actual evaluated-event contract; user data-assembly feedback; LB abbreviation/operation distinctions.

Trade-off: A process record is less literally machine-like than General Machine, deliberately separating data construction from mode identity. The energy trace covers the current electricity evaluation but does not imply all fabrication burdens are known.

**B: Assemble a timed operation — alternate. Machine-bed fragments join a clock, representing construction of a timed process definition.

Influence: Machine power/time route; contrast with measured-energy precedence.

Trade-off: Recognisable time-driven machine, but measured-energy route need not supply time. Too specific to one method to be the stable constructor icon.

Raster observation: 24: inputs + head/bed recognisable. 18: input-to-object direction survives. 16: tiny controls disappear; stable silhouette remains, pending human test.

### RAW End-of-Life Scenario

**A: Use ends; C data branches — recommended. Element reaches a terminal bar; four separated endpoints indicate C1–C4 factor slots. The fan-out expresses scenario coverage after current use, not simulated mass routes.

Influence: Actual four optional factor inputs and missing-module rules; lifecycle boundary research.

Trade-off: Four endpoints are still distinct at 24 px; at 16 px they read as a terminal family. Avoids equating C with recycling or claiming complete C.

**B: End marker and treatment paths — alternate. A boundary stops the current element; two lower ends suggest treatment and disposal options without a recycling loop.

Influence: End-of-current-use metaphor; C-stage treatment/disposal distinction.

Trade-off: Semantically direct end marker; two paths could falsely suggest a two-route calculator rather than C1–C4 evidence. Keep as an illustrative alternative only.

Raster observation: 24: end bar and four endpoints distinct. 18: four terminals still visible. 16: terminal/fan-out survives; do not expect users to count modules.

### RAW Reuse / Recovery Scenario

**A: Same piece, next use — recommended. A material piece leaves one support, crosses a broken system boundary and appears on a second support. It suggests an evidenced continuation beyond current use.

Influence: Actual D assignment; user continuation request; no benefit colour or tick.

Trade-off: One-way transfer distinguishes D from terminal C. Matching pieces cue reuse, but D also includes recovery/recycling credits; it does not promise the same physical item always survives.

**B: Recovery through another cycle — alternate. An open, one-way curve carries a solid used piece toward an outlined future use, across a boundary line.

Influence: User lifecycle continuation; D credit evidence, not recycling logo.

Trade-off: Clear continuation but closer to a familiar circularity arrow; could imply automatic closed-loop benefit. A avoids that misleading reading.

Raster observation: 24: two supports, transfer and boundary distinguish from C. 18: dashed boundary secondary. 16: transfer survives but boundary requires tooltip context.

### General Machine mode

**A: Bench machine definition — recommended. Single supporting frame, operating head and work-bed make an immediately recognisable generic machine. Rounded structural corner and filled head improve silhouette.

Influence: Existing native general machine icon and actual generic power/time/energy inputs.

Trade-off: General operation cue, not a specific CNC claim. More literal than the rejected working gap. Shares tool/bed grammar with specialist modes.

**B: Powered machine cabinet — alternate. A compact cabinet with status dial and operating bay communicates a machine asset/definition.

Influence: User request for recognisable General Machine; no inferred toolpath simulation.

Trade-off: Recognisable industrial object but generic equipment rather than material transformation. More IT/appliance-like than A.

Raster observation: 24: frame/head/bed recognisable. 18: general machine remains. 16: controls are secondary; head/bed gap is maintained.

## Five accepted fabrication concepts

**CNC / Milling**: Retains cutter/workpiece subtraction. Filled spindle, open cutter, stepped stock and one chip: no toolpath-to-energy claim.

**Robotic Process**: Retains articulated base/links/tool. Heavier links and open circular joints make a recognisable arm without a reach-envelope mesh.

**3D Printing**: Retains nozzle/deposited layers. One rounded continuous bead differentiates addition from CNC subtraction.

**Coreless Winding / Fibre Placement**: Retains filaments across discrete anchors and open centre. Curves replace rigid criss-cross geometry; there is no solid mandrel.

**Reclaimed Timber Preparation**: Retains plane and wane-edged stock/offcut. A flowing irregular edge contrasts with the finished baseline without suggesting every reclaimed member is defective.

## Graphic specification

- 24-unit transparent viewport; no baked orange tile or uniform enclosing frame.
- Warm neutral ink `#332C29`; no green benefit claims or arbitrary mode colours. The optional warm-grey secondary tone is for review annotations, not required icon semantics.
- Primary pictorial strokes generally 1.75 units; secondary edges 1.1–1.4; some structural links 2.1–2.5. Filled operating heads and source blocks establish contrast. These are optical choices for the revised icons, not a uniform mathematical line rule. The nine retained prior proposals keep their existing strokes and neutral colour; the contact sheet intentionally exposes that remaining stylistic difference.
- Round pictorial caps/joins; deliberate filled typographic corners. Preserve roughly one pixel or more of useful negative space at 24px. Do not add fine hatching simply to signal sophistication.
- RAW-derived lettering uses ~18% cap-height stems, round counters and a simplified curved W. It is a custom vector alphabet fragment, not an identified official font. DK/ÖB/GWP share weight without enclosing boundaries.
- At 18/16px, primary edges receive a small correction and tertiary detail groups are removed. Each PNG is rendered independently from SVG with supersampling; it is not a resize of a 64px PNG. Optical SVG masters are retained for those two sizes.
- 64px is for inspection, 32px for enlarged UI review, 24px is the main GH raster, 18/16px are stress tests. Full wordmark variants are supplied at these widths for evidence but are not usable small toolbar lettering.

## Evaluation and selection

Seven criteria are applied: function, RAW relationship, 24px clarity, distinction from neighbours, family consistency, graphic quality, native bitmap feasibility. The evaluation file (supporting internal reference retained privately) contains ordinal 1–5 ratings. These are designer judgements informed by code and raster inspection, not measured scientific scores. No totals or automatic ranking are used.

Meaning is a gate. The timed-machine alternative has a clear silhouette but wrongly privileges a time route; measured energy can lack time. The stacked GWP has larger glyphs but breaks the familiar indicator reading. BR18/ÖKO identifies datasets more exactly but is less readable and does not reflect the user’s preferred RAW-derived DK/ÖB direction. Physical Properties B is simpler at 16px; A retains the constructed element as the source, distinguishing it from Material Info. C four endpoints describe four factor slots, not a waste-flow simulation. D transfer avoids the stronger but misleading closed-loop recycling reading of its alternate.

## Small-size review and iteration

The independently rendered sheets were visually inspected. Text/raster overlaps in the first comparison boards were corrected by expanding row spacing. Robot link strokes initially filled the joint centres; they were shortened to preserve genuinely open joints. The nine uncriticised proposal icons are retained byte-for-byte; they are not redesigned in this corrective task. The final boards show both real-size and enlarged views rather than hiding poor recognition with magnification.

At 24px, source lettering, constructors, section silhouette and machine mechanisms are distinguishable in the reviewed samples. At 16px the GWP W, C endpoint count and D boundary dashes are weaker; the broad identity survives but exact meanings require labels. These are explicit limits, not a claim that all meanings passed a user recognition study. The process-record icon especially warrants a human 24px check: its assembly cue is explicit, but the energy trace could be read as a battery. It is deliberately different from the literal General Machine mode.

## Grasshopper implementation feasibility

No implementation is performed. `MachineProcessIcons.cs` currently returns one cached 24 × 24 ARGB bitmap for every mode. The future implementation can cache approved bitmap variants and invalidate the component icon cache after mode changes; it must not draw or allocate new bitmaps continuously during canvas painting. Existing custom selectors use their own attributes, so palette and body icon placement need separate verification. Standard icons are bitmaps, not directly loaded SVG paths.

Recommend the constructor mark in the palette. Keep the data-constructor icon stable in the palette and centre for now; mode identity can remain in the existing footer. The six mode masters are separate proposals. Any later dynamic centre icon must keep constructor meaning clear and needs a separate native caching/layout test. Current general/specialist SVGs are mechanism masters, not proof that mode icons are already supported or deployed. Normal, selected, locked and error states plus Windows 100/150/200% scaling must be checked in Rhino after approval. Current boards use representative backgrounds and an unchanged historical native toolbar crop. They are explicitly composites; no new native GH test was run.

## Proposed approval and unresolved questions

Recommend approving the direction as a coherent package: equal-cap RAW LCA; open DK/ÖB; horizontal GWP; construction/decomposition grammar; terminal C versus beyond-boundary D; refined fabrication mechanisms. Do not treat this recommendation as deployment permission.

Still unresolved: brand-custodian approval of the LCA extension; whether users read the simplified flowing W as W at 16px; recognition of dense process-construction versus its general mode; final C/D metaphor comprehension without explanatory prose; native high-DPI/selected/locked/error appearance and selector-body placement. A short human comparison at real 24px is more valuable than another numerical scoring round.

No production C#, GUIDs, ports, calculations, datasets or bitmap registration were changed. No commit or push. Build/tests were not run because this package contains design assets, audit scripts and documentation only; source/test/data hashes are verified separately.
